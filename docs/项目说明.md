# Keystone 项目说明

[![Release](https://img.shields.io/badge/Release-V3.6.2-green.svg)](https://github.com/bruceblink/Keystone)
[![JDK](https://img.shields.io/badge/JDK-25-green.svg)](https://github.com/bruceblink/Keystone)

Keystone 是一个基于 Spring Boot 3.5 的 Java 后端工程，当前定位是“后台管理框架 + 可发布 Spring Boot starter”的后端框架。

本文档描述当前仓库状态。更偏快速上手的命令入口见 [README.md](../README.md)。

## 当前状态

| 项目 | 当前值 |
| :--- | :--- |
| 项目版本 | `3.6.2` |
| Spring Boot | `3.5.13` |
| 推荐运行 JDK | `25` |
| Java 编译目标 | `17` |
| 构建工具 | Gradle Wrapper |
| 默认服务端口 | `18080` |
| 默认 profile | `dev` |
| 认证方式 | Keystone 本地账号密码 + JWT |

当前主要能力：

* Spring Security + JWT 登录认证、单账号在线会话限制、refresh token。
* 用户、角色、菜单、部门、岗位、字典、配置、公告、日志、在线用户等后台管理能力。
* 定时任务管理和任务日志。
* MyBatis-Plus、动态数据源、Druid、Flyway、Redis、Caffeine、本地 Map 三级缓存。
* 数据库和 Redis 密码支持 `secret:v1:aes-256-gcm` 密文文件。
* Swagger / OpenAPI 可按环境关闭，显式开启后仍受登录态保护。
* Framework starter 可被下游 Spring Boot 应用直接引入。

## 模块结构

```text
Keystone
├── keystone-admin                         # Spring Boot 可执行应用入口和环境配置
├── keystone-framework-spring-boot-starter # 框架聚合 starter
├── keystone-framework-admin               # 框架 Web/API 层、系统 controller、自定义 Web 支撑
├── keystone-framework-domain              # 框架领域服务、系统管理、定时任务、用户/角色/日志等
├── keystone-domain                        # 下游应用扩展模块；开源分支当前不放框架运行时代码
├── keystone-infrastructure                # 基础设施配置、缓存、数据源、Redis、MyBatis、SpringDoc、Flyway
└── keystone-common                        # 通用类型、异常、工具、枚举、JWT/RSA/Excel 等基础能力
```

启动类：

```text
app.keystone.admin.KeystoneAdminApplication
```

## 构建与测试

推荐使用仓库自带 Wrapper：

```bash
./gradlew clean build -x test
./gradlew test
```

Windows：

```powershell
.\gradlew.bat clean build -x test
.\gradlew.bat test
```

说明：

* Gradle 已开启 configuration cache、build cache、parallel 和 daemon。
* 默认 `test` 任务排除 `db-integration` 标签和数据库集成测试源码；数据库集成测试需要单独运行。
* `check` 会运行 test、JaCoCo、Checkstyle、SpotBugs；Checkstyle 和 SpotBugs 当前以报告为主，不阻断构建。

数据库集成测试使用 Docker MySQL 和 Flyway 主迁移脚本。先启动依赖：

```powershell
cd docker
docker compose up -d mysql redis
cd ..
.\gradlew.bat :keystone-domain:integrationTest :keystone-admin:dbIntegrationTest
```

## 配置结构

配置入口在 `keystone-admin/src/main/resources/application.yml`：

```yaml
server:
  port: 18080

spring:
  config:
    import: "classpath:application-basic.yml"
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:dev}
```

公共配置在 `keystone-infrastructure/src/main/resources/application-basic.yml`，环境配置在：

| 文件 | 用途 |
| :--- | :--- |
| `keystone-admin/src/main/resources/application-dev.yml` | 本地 / 开发联调环境 |
| `keystone-admin/src/main/resources/application-prod.yml` | 生产 / 容器部署环境 |
| `keystone-admin/src/main/resources/application-test.yml` | Docker MySQL 数据库集成测试环境 |

当前 profile 口径：

| Profile | 数据库 | Redis | 认证 |
| :--- | :--- | :--- | :--- |
| `dev` | 通过 `SPRING_DATASOURCE_*` 覆盖；当前默认指向开发环境 | 通过 `SPRING_DATA_REDIS_*` 覆盖；当前默认指向开发环境 | 本地账号密码 |
| `prod` | MySQL，密码密文文件默认 `/run/secrets/.database_password.enc` | Redis，密码密文文件默认 `/run/secrets/.redis_password.enc` | 本地账号密码 |
| `test` | Docker MySQL，默认使用集成测试专用库 | Docker Redis，默认 `localhost:6379` | 本地账号密码 |

生产环境必须显式配置 `KEYSTONE_RSA_PRIVATE_KEY`。RSA 私钥用于 `/login` 密码解密，并用于 Keystone access token 的 RS256 签名；公钥由 `/login/rsa-public-key` 提供给前端和其他服务验签。

生成 RSA 密钥对：

```bash
python scripts/secret_tool.py generate-rsa
```

## Docker 运行

Docker Compose 文件位于 `docker/docker-compose.yml`。

服务组成：

| 服务 | 镜像 | 容器名 | 默认宿主端口 |
| :--- | :--- | :--- | :--- |
| MySQL | `mysql:8.4` | `infra_mysql` | `33066` |
| Redis | `redis:8.6.2-alpine` | `infra_redis` | `6379` |
| Keystone backend | `keystone:latest` | `sys_manage_backend` | `18080` |

常用命令：

```bash
cd docker
docker compose up -d mysql redis
docker compose up -d --build
docker compose logs -f sys_manage_backend
docker compose down
```

容器中的后端服务主要通过以下环境变量覆盖运行配置：

* 数据库连接：`SPRING_DATASOURCE_URL` / `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD_FILE` / `KEYSTONE_DATASOURCE_ENCRYPT_KEY_FILE`
* Redis 连接：`SPRING_DATA_REDIS_HOST` / `SPRING_DATA_REDIS_PORT` / `SPRING_DATA_REDIS_PASSWORD_FILE` / `KEYSTONE_REDIS_ENCRYPT_KEY_FILE`
* RSA 私钥：`KEYSTONE_RSA_PRIVATE_KEY`
* 日志路径：`LOG_PATH`

## 认证与会话

| 入口 | 用途 |
| :--- | :--- |
| `POST /login` | 使用 Keystone 本地账号密码登录 |
| `POST /refresh-token` | 刷新 Keystone access token |
| `POST /logout-refresh-token` | 注销 refresh token |
| `GET /login/rsa-public-key` | 获取 Keystone RSA 公钥，用于登录密码加密和 Keystone JWT 验签 |
| `GET /captchaImage` | 获取验证码 |
| `GET /getConfig` | 获取登录页配置 |

当前实现要点：

* Keystone token 和 refresh token 由后端签发，登录态保存在 Redis。
* 同一账号默认只允许一个在线 access 会话；冲突时返回“该账号已经登录”，客户端可用 `forceLogin=true` 显式接管旧会话。
* refresh token 会话用于长时间保持登录，并支持服务端撤销。

详细设计：

* [single-account-login-design.md](single-account-login-design.md)
* [refresh-token-session-design.md](refresh-token-session-design.md)

## 数据库迁移

Flyway 默认迁移路径：

```text
classpath:db/migrate/common
classpath:db/migrate/mysql
```

命名规范：

* MySQL 迁移脚本统一放在 `db/migrate/mysql/`。
* 文件名格式为 `V<版本号>__<描述>.sql`，例如 `V3_5_45__migrate_behavior_item_dictionaries.sql`。
* `__` 前后不能省略，同一版本号不能重复。
* 已执行过的 Flyway 脚本不要重命名、不要改版本号；继续演进时新增更高版本脚本。
* 脚本内容不要写死数据库名，例如不要写 `USE keystone;`。

starter 发布物只携带 `keystone-infrastructure/src/main/resources/db/migrate/common` 和 `db/migrate/mysql` 下的框架/系统迁移。下游应用测试数据应由下游应用自己的测试环境负责。
